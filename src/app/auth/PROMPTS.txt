[3] ONBOARDING PAGE  —  /onboarding
================================================================================
Prompt:
  "Render the Onboarding page (onboarding/page.tsx — server component that passes
  data to OnboardingClient.tsx). This is a post-signup wizard that completes the
  user's profile and role setup before they enter the dashboard.

  Server component (onboarding/page.tsx):
  — Calls getCurrentUserWithProfile(). If !user → redirect('/sign-up').
  — Reads pendingRole = sessionStorage['propati_pending_role'] (read on server
    via cookies or passed through Clerk session; fallback to user.role if already set).
  — If user.role is already set (not 'tenant' default), redirect to
    getRoleRedirectPath(user.role) to skip onboarding.
  — Server fetches: prisma.user.findUnique({ where: { id: user.id },
    select: { fullName, email, phone, avatarUrl, role, isActive } }).
  — Wraps in DashboardShell is NOT needed — this is a standalone auth-flow page
    on a dark background (bg-black min-h-screen).
  — Passes { user, pendingRole } props to OnboardingClient.

  OnboardingClient (onboarding/OnboardingClient.tsx — 'use client'):
  — State: activeStep (1 | 2 | 3), formData ({ fullName, phone, avatar, bio }),
    isSubmitting (boolean).
  — Reads pendingRole from props. Steps are tailored per role.

  Layout: <div className='min-h-screen bg-black flex items-center justify-center
    px-4 py-12'> with a centered glass-card container (max-w-lg w-full).

  — Progress bar at top: 3 steps with circular nodes + labels.
    Step 1: 'Welcome' (UserIcon), Step 2: 'Profile' (UserIcon),
    Step 3: 'Complete' (Sparkles). Active step = emerald fill, completed = green
    check, pending = gray. Connector line h-0.5 between steps.
  — Step indicator text: 'Step {activeStep} of 3'.

  Step 1 — Welcome:
  — h1 'Welcome to PropatiBox' (text-3xl font-bold text-white).
  — body: 'Let's get you set up. We'll ask a few quick questions to personalize
    your experience.' (text-zinc-400).
  — Illustration: PropatiBox house-key SVG icon centered (w-12 h-12, emerald-500).
  — Role display card (non-editable since chosen at sign-up):
    glass-card with role label (Landlord/Tenant/Agent/Estate Manager) + icon +
    description of what this role sees.
  — 'Continue' button (emerald, full width) → setActiveStep(2).

  Step 2 — Profile:
  — h2 'Tell us about yourself' (text-xl font-bold text-white).
  — body 'Complete your profile so we can match you with the right properties.'
  — Form fields (each with label, input, error message):
    — Full Name: input type='text' (defaultValue={user.fullName}), required,
      placeholder 'e.g. Adeola Balogun'.
    — Phone Number: input type='tel' (defaultValue={user.phone || ''}),
      required, placeholder '+234 XXX XXX XXXX'.
    — Bio: textarea (rows 3, placeholder 'Brief description of yourself...'),
      optional, max 200 chars with character counter.
    — Avatar upload: drag-drop zone (cursor-pointer, dashed border,
      rounded-xl) or click to upload. Shows current avatar if user.avatarUrl.
  — Validation: fullName required (min 3 chars), phone required (Nigerian format
    regex /^(\+?234|0)[7-9][0-1][0-9]{8}$/).
  — Error messages: text-xs text-red-400 below each field.

  Step 3 — Complete:
  — h2 'All set!' (text-2xl font-bold text-white).
  — body 'Your profile has been configured. Let's take you to your dashboard.'
  — Loading spinner (Loader2 animate-spin, emerald-500) during submission.
  — On completion: fade-in success checkmark (CheckCircle2, green, scale-in).

  Navigation:
  — Back button (outline, ChevronLeft icon) on steps 2 and 3 → setActiveStep(prev-1).
  — Continue/Next button (emerald, full-width) → validates current step,
    advances. On step 3: calls handleComplete().

  handleComplete():
  — Sets isSubmitting true.
  — PATCH /api/onboarding (or POST /api/profile) with { fullName, phone, bio,
    avatar } from formData.
  — Also POST /api/onboarding/role with { role: pendingRole } if user.role is
    still the default 'tenant' or unset.
  — On success: router.replace(getRoleRedirectPath(pendingRole || user.role)).
  — On error: toast error + set isSubmitting false.

  Styling details:
  — Glass card: 'glass-card p-8 rounded-2xl border border-white/[0.08]'.
  — Inputs: h-12 rounded-xl, border border-white/[0.12], bg-zinc-900/90,
    text-white placeholder:text-zinc-500, focus:ring-2 focus:ring-emerald-500.
  — Labels: text-xs font-medium text-zinc-400 uppercase tracking-wider.
  — Continue button: 'w-full h-12 rounded-xl bg-emerald-500 hover:bg-emerald-600
    text-white font-semibold text-base transition-all duration-200'.
  — Back button: 'px-4 py-2 border border-white/[0.1] rounded-lg text-zinc-300
    hover:text-white hover:bg-zinc-900' with ChevronLeft icon (w-4 h-4 ml-1).

  All form submission POSTs to real API endpoints (no setTimeout or alert).
  The role is persisted to Prisma via POST /api/onboarding/role which validates
  against SELF_SERVICEABLE_ROLES (landlord|tenant|agent|estate_manager)."
