1. DASHBOARD — /dashboard/agent
================================================================================
File: page.tsx + AgentDashboardClient.tsx
Navigation: AGENT_NAVIGATION — Main > Dashboard

Layout: Full-width dashboard shell with glass-morphism stat cards at top,
  followed by a two-column grid of activity + pipeline widgets.

Components:
  - Stat cards (Total Managed Properties, Active Deals, Pending Commissions,
    This Month Earnings) using formatCurrency util (en-NG, NGN).
  - Recent Deals table — maps agreements where agentId = user.id, status in
    ACTIVE_STATUSES. Columns: Property, Client, Status, Value, Last Updated.
    Links to /dashboard/agent/deals/[id].
  - Upcoming Appointments card — shows next 3 calendar events from
    /api/agent/schedule (if implemented) or verification.inspection records
    where l4AgentId = user.id.
  - Pipeline Summary — quick stats from buy/sell pipelines.
  - Quick Actions buttons: "Schedule Inspection", "View Commissions",
    "New Agreement" → /dashboard/agent/agreements/new.

Server data (page.tsx fetches via Prisma):
  - prisma.agreement.findMany({ where: { agentId: user.id, status: { in: ACTIVE_STATUSES } } })
  - prisma.verification.findMany({ where: { l4AgentId: user.id }, orderBy: { l4ScheduledAt: 'desc' } })
  - prisma.walletTransaction.aggregate or findMany for commission totals.

API endpoints used:
  - GET /api/agent/dashboard (server-side Prisma only, no client fetch)

Interactions:
  - Clicking a deal row → navigate to /dashboard/agent/deals/[id]
  - "Schedule Inspection" → navigate to /dashboard/agent/inspections/new
  - "View Commissions" → navigate to /dashboard/agent/commissions

2. MANAGED PROPERTIES — /dashboard/agent/properties
================================================================================
File: page.tsx + AgentPropertiesClient.tsx
Navigation: AGENT_NAVIGATION — Main > Managed Properties

Layout: Dashboard shell with hideGlobalSearch flag. Stat summary row,
  then a table/list hybrid of all properties where the agent is assigned
  via AgentAssignment (active scope) OR listing.agentId = user.id.

Server data (page.tsx fetches via Prisma):
  - prisma.listing.findMany({
      where: {
        OR: [
          { agentId: user.id },
          { assignments: { some: { agentId: user.id, status: 'active' } } }
        ]
      },
      include: {
        owner: { select: { id, fullName, email, avatarUrl } },
        agent: { select: { id, fullName, email } },
        images: { where: { isCover: true }, take: 1, select: { id, url } },
        units: { select: { id, unitNumber, buildingName, type, listingType, rent, status, occupancy, isListed, organizationId, currentTenant } },
        assignments: { where: { agentId: user.id, status: 'active' }, select: { id, permissions, scope } },
      }
    })
  Normalized output passed to client: id, title, address, area, state,
    listingType, propertyType, price, pricePeriod, status, verificationTier,
    viewsCount, createdAt, owner, agent, coverImage, unitCount, vacantUnitCount,
    listedUnitCount, permissions, units[].

Components:
  - Stat cards: Total Properties, Vacant Units, Listed Units, Managed Value
  - Filter bar: search by property name/address, filter by listing type,
    filter by status, filter by verification tier.
  - Property card/grid with cover image, verification badge, owner/agent info,
    unit summary (vacant/occupied), and quick action buttons.

API endpoints used:
  - None (server-side Prisma fetch only)

Interactions:
  - Click property card → /dashboard/agent/properties/[id]
  - "View Units" → expand inline unit list
  - "Contact Owner" → open messages with pre-filled listing context
  - "Schedule Inspection" → /dashboard/agent/inspections/new?listingId=[id]

3. PROPERTY DETAIL — /dashboard/agent/properties/[id]
================================================================================
File: page.tsx + AgentPropertyDetailClient.tsx
Navigation: AGENT_NAVIGATION — Main > Managed Properties (detail)

Layout: Dashboard shell (hideGlobalSearch) with tabbed interface:
  Overview | Units | Applications | Agreements | Bookings | Maintenance |
  Conversations | Documents

Server data (page.tsx fetches via Prisma):
  - prisma.listing.findUnique({
      where: { id: params.id },
      include: {
        owner: { select: { id, fullName, email, phone, avatarUrl } },
        agent: { select: { id, fullName, email, phone, avatarUrl } },
        images: { where: { isCover: true }, take: 1, select: { id, url } },
        units: { orderBy: { unitNumber: 'asc' }, select: { ...all unit fields... } },
        assignments: { where: { agentId: user.id, status: 'active' }, select: { id, permissions, scope } },
        applications: { orderBy: { createdAt: 'desc' }, take: 5, select: { id, status, createdAt, applicant: { select: { fullName, email } } } },
        agreements: { orderBy: { createdAt: 'desc' }, take: 5, select: { id, status, createdAt, partyA, partyB } },
        bookings: { orderBy: { checkIn: 'desc' }, take: 5, select: { id, status, checkIn, checkOut, totalPrice, tenant } },
        maintenanceTickets: { orderBy: { createdAt: 'desc' }, take: 5, select: { id, status, priority, title, createdAt } },
        conversations: { orderBy: { lastMessageAt: 'desc' }, take: 5, select: { id, subject, lastMessage, lastMessageAt, participants } },
        documents: { orderBy: { createdAt: 'desc' }, take: 5, select: { id, type, name, url, createdAt } },
      }
    })
  Authorization: redirect to getRoleRedirectPath(user.role) if role !== 'agent'.

Components:
  - Hero section with cover image gallery, property title, address, price.
  - Verification tier badge (Tier 1 / Tier 2 / Verified).
  - Stats row: Unit Count, Vacant, Occupied, Listed, Views.
  - Tab navigation with sticky headers per tab.
  - Each tab renders its own sub-component/section.
  - "Edit Property" button → /dashboard/agent/properties/[id]/edit (if permissions include write).
  - "Schedule Inspection" button → /dashboard/agent/inspections/new?listingId=[id].

API endpoints used:
  - None (server-side Prisma fetch only)

Interactions:
  - Click tab → switch view
  - Click unit row → expand unit detail modal
  - Click application row → /dashboard/agent/clients (or deal detail)
  - Click agreement row → /dashboard/agent/deals/[id]
  - Click "Contact Owner" → /dashboard/agent/messages
  - Click "Schedule Inspection" → /dashboard/agent/inspections/new?listingId=[id]

4. PIPELINE — /dashboard/agent/pipeline
================================================================================
File: page.tsx + AgentPipelineClient.tsx
Navigation: AGENT_NAVIGATION — Sales & CRM > Pipelines > All Deals

Layout: Dashboard shell with filterable pipeline kanban/board or table view.
  Deals are Agreement records where agentId = user.id, grouped by stage:
  enquiries → viewings → offers → agreements → closed.

Server data (page.tsx fetches via Prisma):
  - prisma.agreement.findMany({
      where: { agentId: user.id },
      select: { id, type, status, createdAt, rentAmount, cautionDeposit, startDate, endDate, listing: { select: { title, address } }, landlord: { select: { fullName } }, tenant: { select: { fullName } } },
      orderBy: { createdAt: 'desc' }, take: 100
    })

Components:
  - Kanban board with 5 columns (Enquiries, Viewings, Offers, Agreements, Closed).
  - Each card shows: property address, client name, deal value, status badge.
  - Filter bar: by type (rental/sale/short_let), by date range, by agent.
  - Stats summary: total deals, in-progress count, closed count, total value.
  - Column headers show count + sum of deal values.

API endpoints used:
  - GET /api/agent/agreements (server-side Prisma, agentId filter)

Interactions:
  - Click card → /dashboard/agent/deals/[id]
  - Drag card between columns (client-side optimistic update via PATCH)
  - Filter dropdown changes → re-query /api/agent/agreements?status=[stage]
  - "New Deal" button → /dashboard/agent/agreements/new
