[1] LANDLORD DASHBOARD  —  /dashboard/landlord/
================================================================================
Prompt:
  "Render the Landlord Dashboard (page.tsx server component + LandlordDashboardClient.tsx
  client component) inside DashboardShell with LANDLORD_NAVIGATION. Auth: getCurrentUser()
  via server component, redirect('/sign-in') if no user, redirect to getRoleRedirectPath
  if role !== 'landlord'. Data fetched server-side via Prisma:

  - listingCount = prisma.listing.count({ where: { ownerId: user.id } })
  - activeListingCount = prisma.listing.count({ where: { ownerId: user.id, status: 'active' } })
  - pendingApplicationCount = prisma.application.count({ where: { landlordId: user.id, status: 'pending' } })
  - openMaintenanceCount = prisma.maintenanceTicket.count({ where: { listing: { ownerId: user.id }, status: { in: ['open', 'assigned', 'in_progress'] } } })
  - totalRevenue = prisma.transaction.aggregate({ where: { payeeId: user.id, status: 'released', createdAt: { gte: startOfMonth } }, _sum: { amount: true } })
  - recentListings: 12 listings, select { id, title, listingType, status, price, createdAt }
  - maintenanceTickets: 5 open tickets, select { id, title, listing { title }, priority, status, tenant { fullName } }
  - recentTenants: 5 tenant agreements with tenant { fullName, avatarUrl }, listing { title }, rentAmount

  Client component (LandlordDashboardClient) receives props: displayName, totalRevenue,
  listingCount, activeListingCount, occupancyRate, pendingApplicationCount,
  openMaintenanceCount, recentListings, maintenanceTickets, recentTenants.

  Layout: PageHeader ('Landlord Dashboard' + greeting) with InteractiveHoverButton
  action (Add Property if empty, Add Listing otherwise).

  Two modes:
  — Empty state (listingCount === 0): onboarding card with 3-step progress bar
    (Add Property → Publish Listing → Setup Payout Bank) + grid of linked steps
    with step numbers, done status based on listingCount > 0 / activeListingCount > 0
    / totalRevenue > 0.
  — Full dashboard (listingCount > 0): 4-column StatCard grid (Total Properties,
    Active Listings, Monthly Revenue, Occupancy Rate), then a 2-column grid:
    LEFT — Revenue Trend chart (placeholder when no revenue, 'Monthly breakdown
    arrives with your next billing cycle') with 'View all' link to /financials;
    RIGHT — Actionable Insights card with conditional quick-action links
    (maintenance tickets → /maintenance, applications → /applications,
    no active listings → /listing/new, all-caught-up empty state).

  Below: 3-column grid — Portfolio Health card (Occupancy progress bar only,
  hard-coded bars removed), Recent Maintenance card (table: ticket title, listing,
    priority badge, status, raised by, date), Recent Tenancies card (table:
    tenant avatar + name, listing title, rent amount).

  All cards: glass-card, border-zinc-200 dark:border-[#27272a], bg-white
  dark:bg-[#F8FAFC] dark:bg-black, p-5, font-semibold text-sm headers.
  Priority badges: urgent=tag-red, high=tag-red, medium=tag-amber, low=tag-emerald.
  formatCurrency() for NGN formatting."

TECHNICAL NOTES
================================================================================
— All pages follow the pattern: server component (page.tsx) → getCurrentUserWithProfile()
  → role check (redirect('/dashboard') if not 'landlord', redirect('/sign-in') if !user) →
  DashboardShell(navigation=LANDLORD_NAVIGATION, userRole='landlord', userName) →
  ErrorBoundary → client component.

— (dashboard)/layout.tsx remains a thin 9-line auth-only server component.
  Never add UI to layout.tsx — causes double sidebar.

— withAuth(request) used on API routes for role-based authorization.
  Never derive role from Clerk unsafeMetadata — use publicMetadata only.

— redirect() must NEVER be inside a try block. Resolve target into a variable,
  then redirect() after try/catch.

— getRoleRedirectPath() in src/lib/auth.ts is the single source of truth.

— formatNaira/parseKoboToNaira from @/lib/utils for all currency.
— date.toLocaleDateString('en-NG') for all dates.
— All interactive actions POST/GET/PATCH to real API endpoints — no setTimeout, no alert().
— Components from @/components/ui (Button, Input, Select, Badge, Card, etc.).
— Icons from lucide-react.
— Navigation via <Link> from next/link, router.push/replace from next/navigation.
